# STU 공통 작업 규칙

이 문서는 STU 저장소에서 작업하는 모든 사람과 AI 에이전트(Codex, Claude Code)가 따르는
단일 규칙이다. `AGENTS.md`와 `CLAUDE.md`는 이 문서를 가리키는 진입 파일일 뿐이며, 규칙을
따로 두지 않는다.

## 0. 문서 위계

규칙이 충돌하면 위에 있는 문서가 우선한다.

1. `docs/PROJECT_RULES.md`(이 문서)
2. `docs/validation/DECISION_LOG.md`의 최신 승인 결정
3. `docs/methodology/`의 활성 방법론 문서
4. `configs/parameters.yaml`(상수와 임계값의 단일 출처)
5. `docs/methodology/spec/`의 지표정의서·구현사양서
6. `docs/legacy/`, `archive/legacy/`(읽기 전용 기록, 규칙의 근거로 쓰지 않음)

`docs/methodology/spec/`의 지표정의서 v0.4와 구현사양서 v0.2는 CEI를 주지표로 둔다. 이
부분은 `docs/validation/PHASE1_REGISTRATION_DIAGNOSIS_20260814.md`의 결론(CEI 산출 불가)으로
효력이 정지되었으며, 개정 전까지 이 문서의 3절이 우선한다.

## 1. 프로젝트 전제

- 대상지는 개선공사로 형상이 바뀌었고 추가 촬영은 없다. 영상 8편은 재취득할 수 없다.
- 원본 영상(`data/raw/`), DJI SRT, 현장 실측값은 수정·삭제·재인코딩하지 않는다. 무결성은
  `manifests/raw_videos.csv`의 sha256으로 확인한다.
- 클립 메타데이터와 분석 가능 구간의 정본은 `manifests/clips.yaml`이다.
- 연구 목표는 (1) 개선 전 현황 진단, (2) 영상 기반 분석 방법론 검증이다.

## 2. 파이프라인 단계

다음 단계를 구분하고 각 단계의 산출물을 별도로 보존한다.

1. raw detections
2. raw tracker trajectories
3. filtered trajectories
4. merged trajectories
5. reviewed trajectories(횡단보도 영향권, 사람 보정)
6. crossing events
7. interaction candidates
8. reviewed interaction events
9. 지표

- 코드, 테스트, 예제 산출물, 검증 근거가 없는 단계를 "구현됨"으로 쓰지 않는다.
- 앞 단계의 누락을 뒤 단계에서 숨기지 않는다. 단계별 생존율과 제외 사유를 남긴다.
- 필터는 원본 궤적을 지우는 단계가 아니다. 필터 결과는 별도 파일로 쓰고, 제외된 궤적에는
  사유를 기록한다. 짧은 트랙은 삭제하지 않고 `short_track` 등의 플래그로 표시한다.

## 3. 지표 범위

| 지표 | 상태 |
|---|---|
| 객체·궤적 품질, 노출(보행량·차량량), 상호작용 목록, A/B 선후관계 | 산출 대상 |
| 양보·정지·대기 행태 | 산출 대상, 신뢰구간 병기 |
| PET, TTC, 최소거리 | 보조 지표. 사람 검토로 확정한 사건만 결과로 보고 |
| `provisional_dpd` | 접근로별 미터 환산이 검증된 사건에만 |
| CEI(PSD<1 통과율) | 산출하지 않음(`NOT_OBSERVABLE`). D30이 화면 밖 |
| 지점 PDI, 안전등급, 3곳 통계적 순위, 개선 전후 비교 | 산출하지 않음 |

- 표본이 부족하거나 산출할 수 없는 값은 0이나 빈칸이 아니라 사유 코드로 쓴다:
  `INSUFFICIENT_SAMPLE`, `GATE_FAILED`, `NOT_OBSERVABLE`, `REQUIRES_FIELD_SURVEY`,
  `REQUIRES_LONGER_OBS`, `PENDING_VERIFICATION`.
- 서로 다른 지표를 가중합한 종합점수를 만들지 않는다.
- 3곳 비교는 점추정 순위가 아니라 신뢰구간과 함께 기술한다.
- 트랙 수나 위험 후보 수의 증가를 품질 향상으로 보지 않는다.

### DPD

```python
# 계수는 configs/parameters.yaml 의 dpd_coefficients 에서 읽는다. 아래는 참조용.
DPD_A1 = 1/(1+exp(1.196*S_m - 0.075*V_m - 0.923))   # 원문 식(2)
DPD_B1 = 1/(1+exp(0.862*S_m - 0.052*V_m))           # 원문 식(3)
DPD_B2 = 1/(1+exp(0.561*a5 + 2.713))                # project_corrected_b2_v1
DPD_A0 = DPD_B0 = 0
```

- 원문 식(4)는 계수 두 개가 바뀐 표기로 판단해 수정식을 쓴다. 근거는
  `docs/methodology/pdi_dpd_verification_v01.md` 2.3절. 출판사 공식 정오표라고 쓰지 않는다.
- 결과마다 `formula_version`을 저장한다.
- 계수는 폴란드 자료로 보정된 값이다. 한국 현장 보정값으로 주장하지 않는다.
- 회전 차량에는 DPD를 적용하지 않는다.
- DPD는 설문 기반 인지위험이다. DPD 0.5를 사망확률 50%로 해석하지 않는다.

## 4. 궤적 확보(현장 미세조정 + 사람 보정)

- **GT가 먼저다.** 모델, FPS, 임계값 비교는 모두 같은 블라인드 GT 표본에서 한다.
- GT를 만드는 사람은 자동 추적 결과를 보지 않는다(블라인드). 절차는
  `docs/validation/OBJECT_TRACK_GT_PROTOCOL.md`를 따른다.
- 미세조정용 라벨은 기존 추적 결과를 초벌로 쓰고 사람이 수정해 만든다. 초벌 출처와 수정 여부를
  라벨마다 기록한다.
- **학습과 평가를 분리한다.** 성능 평가는 학습에 쓰지 않은 클립 또는 시간 구간에서만 한다.
  분할 정의는 설정 파일에 저장하고 바꾸지 않는다. GT 표본은 학습에 넣지 않는다.
- 사람 보정은 자동 산출물을 덮어쓰지 않는다. `reviewed trajectories`는 원래 track_id, 수정 유형
  (병합·분할·클래스 변경·구간 보간·삭제), 검토자, 검토일을 함께 저장한다.
- 보간한 구간은 관측 구간과 구분해 표시한다.

## 5. 측정과 단위

- 좌표계를 항상 구분해 표기한다: `source_px`, `reference_px`, `world_m`. 원본 화소 좌표로
  지표를 계산하지 않는다.
- 정합 기준 프레임은 `DJI_0481` frame 2848이다.
- 화면 전체에 단일 스케일을 쓰지 않는다. 미터 환산은 접근로별 스케일로 하며, 검증 전 값은
  `null`과 `scale_verified: false`로 둔다.
- 화소 임계값을 미터 단위 산출물에 그대로 쓰지 않는다. 단위가 바뀌면 이름도 바꾼다.
- 속도는 m/s다. km/h 입력을 막는 단위 assert를 둔다.
- 가속도는 진행방향 성분을 쓴다. `a5`는 감속일 때 음수다.
- 통과시점 `t_m`은 선형보간한다. 가장 가까운 프레임으로 반올림하지 않는다.
- fps는 30000/1001이다. 30으로 하드코딩하지 않는다.
- 클래스는 트랙 단위 확정값을 쓴다. 프레임 단위 원시 클래스를 직접 쓰지 않는다.

## 6. ROI와 보정자료

- 정본 ROI는 `data/calibration/rois_split.json`(ST_Roundabout 판, 2026-10-27 결정)이다.
- ROI는 노면표시 실체에 맞춘다. 오탐을 줄이려고 ROI를 좁히거나 교차각 필터를 넣지 않는다.
  보행자와 차량의 구분은 각도가 아니라 횡방향 이격거리로 한다.
- 위치별 제외 마스크를 추가할 때는 근거(확인된 고정 오탐)와 적용 영상을 기록한다.
- 정본이 정해지지 않은 보정자료(`alignment_homographies.json`, `roadway_mask.png`)는 새 분석에
  쓰기 전에 결정을 받는다.

## 7. 설정과 파라미터

- 상수와 임계값은 코드에 하드코딩하지 않는다. `configs/`에서 읽는다. 필요한 값이 없으면
  근거등급(A/B/C)과 출처를 붙여 설정에 추가한다.
- 설정 파일은 제자리에서 고치지 않는다. 값을 바꾸면 버전을 올리고 changelog에 사유를 쓴다.
- 결과가 좋아지는 방향으로 임계값을 조정하지 않는다. 변경할 때는 민감도 분석을 함께 낸다.

## 8. 변경 승인 경계

모델, FPS, confidence, 추적·필터·병합 임계값, 좌표 보정, 학습/평가 분할, 지표 공식, 품질
게이트를 바꾸기 전에 다음을 보고하고 사용자 승인을 받는다.

1. 영향을 받는 파이프라인 단계
2. 현재 기준선과 변경안
3. 검증 표본과 지표
4. 전체 영상 GPU 실행이나 학습이 필요한지와 예상 시간

승인된 결정은 `docs/validation/DECISION_LOG.md`에 기록한다. 체크포인트에서는 멈추고 보고한다.
끝까지 밀어붙이지 않는다.

## 9. 산출물과 재현성

- 기존 산출물을 덮어쓰지 않는다. 새 설정은 새 출력 정체성(경로·ID)을 쓴다.
- 모든 산출 파일에 `.meta.json`을 붙인다: 생성 시각, 코드 커밋, 설정 파일과 해시, 입력 파일과
  sha256, 좌표계, 단위, 검토 상태. meta가 없는 수치는 보고서에 쓰지 않는다.
- 실제 확인 결과, 미검증 후보, 예시자료를 화면과 보고서에서 구분한다.

## 10. 테스트와 완료 조건

- 테스트는 `unittest.TestCase`로 쓰고 pytest로 실행한다. 파일은 `tests/test_<module>.py`.
- 부호가 뒤집혀도 오류 없이 틀리는 부분(A/B 선후관계, `a5` 부호, 단위)은 테스트를 먼저 쓴다.

작업을 완료로 보고하기 전에:

1. 관련 단위·회귀 테스트 통과
2. 같은 GT 표본에서 현재 기준선과 비교
3. 바뀐 설정과 파이프라인 단계 보고
4. 출력 스키마 보존 또는 의도적 변경의 버전 기록
5. 재현 가능한 예제 산출물과 짧은 검증 요약 저장
6. 한계와 제외 범위 보고
7. README의 "현재 상태"와 `DECISION_LOG.md` 갱신

## 11. 코드 스타일

- PEP 8, 들여쓰기 4칸, `from __future__ import annotations`, `pathlib.Path`.
- 모듈·함수·변수는 `snake_case`, 클래스는 `PascalCase`, 상수는 대문자.
- 경로는 `roundabout.paths`로 해석한다. 절대경로를 하드코딩하지 않는다.
- 재사용 로직은 `src/roundabout/`, 일회성 도구는 `scripts/`에 둔다.

## 12. Git

- 커밋 제목은 짧은 명령형(`fix:`, `feat:`, `docs:`, `refactor:` 등)으로 쓴다.
- 코드 변경과 생성 산출물을 한 커밋에 섞지 않는다.
- 원본 영상, 가중치, 가상환경, `outputs/`, 5MB 초과 이미지, 저작권 자료(논문 PDF 등)를
  커밋하지 않는다.

## 13. 작업 주체와 역할

저장소에 코드를 쓰고 커밋하는 실행자는 **Codex 하나**다. 2026-10-27 결정.

| 주체 | 역할 |
|---|---|
| 사용자 | 승인과 판단, Codex 실행, 사람 작업(블라인드 GT, 궤적 보정, 설계도서 확보) |
| Codex | 유일한 실행자. 코드, 테스트, 파이프라인 실행, 커밋·푸시 |
| Aside | 검토와 관리. GitHub 변경 검토, 작업 지시문과 결정 기록 초안, 외부 조사. 저장소에 직접 커밋하지 않는다 |
| Claude Code | 대기. 정합·스케일 등 깊은 진단 검토가 필요할 때만 사용자가 요청해 사용. 코드를 직접 고치지 않는다 |

### 작업 지시문

- 작업은 `docs/tasks/TASK-NNN.md` 지시문 단위로 진행한다. 형식은 `docs/tasks/README.md`를 따른다.
- 지시문 범위 밖의 변경은 하지 않는다. 필요하면 멈추고 보고한다.
- 작업 하나에 브랜치 하나(`task/NNN-짧은설명`)를 쓰고, 사용자가 확인한 뒤 `main`에 합친다.
- 작업을 마치면 지시문 끝의 "완료 보고"를 채우고 함께 커밋한다.

### 공통

- 진단에 쓴 스크립트와 원자료는 세션 임시폴더(`/tmp` 등)에 두지 않고 저장소의
  `scripts/diagnostics/`와 `outputs/`에 저장한다.
- 작업을 마치면 README의 "현재 상태"를 실제와 맞춘다. 문서가 실제 상태보다 뒤처지지 않게 한다.
- 저장소 밖(채팅 서비스의 프로젝트 지식 등)에 명세 사본을 두고 그쪽을 기준으로 작업하지 않는다.
  정본은 이 저장소다.
