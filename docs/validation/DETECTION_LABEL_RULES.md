# 검출 박스 라벨 작성 규칙 v1

- 문서 상태: 승인(사용자 결정 2026-11-05)
- 작성: Aside / 승인: 사용자
- 적용 범위: (1) 평가용 GT v2(R01 위치 박스 재검토), (2) 미세조정 학습 라벨
- 근거: GT v1 박스가 넉넉함(person AI/GT 면적비 중앙값 0.56, 이전 박스 복사 673/960, 발점 버그 수정 전 입력 115).
  `docs/validation/R01_DETECTION_ONLY_RESULT.md` 참조.

## 1. 기본 원칙

1. **보이는 부분만(modal) 박스를 그린다.** 가려진 부분을 추정해 넓히지 않는다(amodal 금지).
2. 박스는 축 정렬 사각형이다. 회전 박스는 쓰지 않는다.
3. 박스 네 변은 보이는 객체의 가장 바깥 픽셀에 맞춘다. 여유는 원본 3840×2160 기준 **변마다 최대 2 px**이다.
4. 그림자와 반사(유리·물웅덩이)는 박스에 넣지 않는다.
5. 발점 위치를 맞추려고 박스를 키우지 않는다. 발점은 박스 하단 중앙 자동값이며 입력 대상이 아니다.
6. 자동 검출 결과를 보지 않는다(평가 GT). 학습 라벨은 모델 초벌을 쓰되 출처와 수정 여부를 기록한다(PROJECT_RULES §4).

## 2. 클래스(COCO 기준, 사용자 결정 D1)

| 클래스 | 포함 | 비고 |
|---|---|---|
| `person` | 보행자, 서 있는 사람, PM 탑승자, 유모차·휠체어 이용자 | 양산·우산은 3절. 이륜차 탑승자는 제외(4절) |
| `bicycle` | 자전거와 탑승자를 합친 범위 | 4절 |
| `car` | 승용차, SUV, 승합차(밴) | 밴은 `car` |
| `motorcycle` | 오토바이·스쿠터와 탑승자를 합친 범위 | 4절 |
| `bus` | 노선·셔틀·관광버스 | R01에는 없음. 영상 후반부 등장 |
| `truck` | 화물 적재함이 있는 차(픽업, 화물차, 탑차) | 픽업·화물차·탑차는 `truck` |

- 평가 호환표(GT `car` ↔ 검출 `car`·`bus`·`truck`)는 그대로 둔다.
- 전동킥보드 등 PM 자체는 라벨하지 않고 탑승자만 `person`으로 그린다. 속성 `pm=true`를 남긴다.

## 3. 양산·우산 보행자(사용자 결정 D3)

- 클래스는 `person`, 박스는 **양산과 보이는 몸 전체**를 감싼다.
- 속성 `umbrella=true`를 기록한다. 표본 수를 본 뒤 별도 학습 클래스로 분리할지 따로 정한다.

## 4. 이륜차·자전거(사용자 결정 D4, 2026-11-05 확정. 자전거 포함)

- 이 문서에서 **탑승자**는 이륜차에 탄 사람 전체, 즉 운전자와 뒤에 탄 동승자를 모두 말한다.
- `motorcycle`·`bicycle` 박스는 **차체와 탑승자(운전자·동승자)를 합친 범위 하나**로 그린다.
- 탑승자에게는 `person` 박스를 따로 그리지 않는다. 탑승자는 이륜차 객체의 일부다.
- 탑승자가 차체를 가리는 것은 가림으로 보지 않는다. 5절의 무시영역 기준은 다른 물체에 의한 가림에만 적용한다.
- COCO와 다르다. COCO는 탑승자를 별도 `person` 인스턴스로 라벨하고 차량은 보이는 차체만 라벨한다. 사전학습 모델은 탑승자를
  person으로 검출하는 경향이 남을 수 있으므로, 미세조정 후 `rider_inside_vehicle` 건수를 확인한다.
- 자전거를 끌고 가는 사람(타지 않음)은 `person`과 `bicycle`을 각각 그린다.
- 근거: R01 GT v1에서도 motorcycle 3대(36 anchor)에 겹치는 person GT가 없어, 실제 입력은 이미 이 방식이었다
  (Aside 집계, 같은 프레임 person 박스가 motorcycle 박스에 30% 이상 들어간 경우 0건).

## 5. 가림과 무시영역(사용자 결정 D2)

| 상황 | 처리 |
|---|---|
| 보이는 부분이 대략 절반 이상이고 육안으로 객체를 인식할 수 있음 | 보이는 부분에 맞춰 박스 |
| 보이는 부분이 절반 미만 | 무시영역 |
| 절반 이상 보여도 육안으로 객체 인식 불가(흐림, 수관 아래 어둠, 형체 구분 불가 등) | 무시영역 |
| 위치 자체를 판독할 수 없음 | 박스 없음(평가 GT에서는 skip, 기존 사유 사용) |
| 서로 구분할 수 없는 군집 | 군집 전체를 무시영역 1개로 |

- **무시영역도 박스를 그리고 `ignore=true`로 표시한다.** 위치가 있어야 학습에서 가리고 평가에서 오탐 판정을 뺄 수 있다.
- 무시영역 박스는 **추정 범위를 넉넉하게** 그려도 된다. 1절의 2 px 여유 기준을 적용하지 않으며, IoU·위치 지표에 쓰지 않는다.
- 다만 다른 객체의 명확히 보이는 부분은 덮지 않는다. 겹치면 학습 마스킹에서 라벨된 박스 영역은 칠하지 않는다.
- 대략의 범위조차 정할 수 없으면 무시영역이 아니라 박스 없음(skip)이다.
- 학습: 무시영역 픽셀을 학습 타일에서 회색으로 칠한다(YOLO 라벨에는 무시영역 칸이 없음).
- 평가: 무시영역 GT는 분모에서 빼고, 겹치는 검출은 오탐으로 세지 않는다.

## 6. 전수 라벨(학습 라벨)

- 학습에 쓰는 타일 안의 대상 객체는 **빠짐없이** 라벨한다. 주차 차량, 정지한 사람, ROI 밖 객체를 포함한다.
- 빠뜨린 객체는 모델이 배경으로 학습한다. 판단이 어려우면 빠뜨리지 말고 무시영역으로 둔다.

## 7. 라벨하지 않는 것

차량 안 탑승자, 조형물·마네킹, 표지판·광고의 사람 그림, 그림자, 노면표시(과속방지턱 포함), 식생.

## 8. 경계

- 화면 가장자리에서 잘린 객체는 보이는 부분만 박스로 그리고 `truncated=true`를 남긴다. 인식 기준은 5절을 따른다.
- 1024 타일 경계에서 잘린 박스의 유지 기준은 미세조정 TASK에서 Codex가 근거와 함께 제안하고 사용자가 승인한다.

## 9. 기록 필드

| 필드 | 값 |
|---|---|
| `ignore` | true/false |
| `attributes` | `umbrella`, `pm`, `truncated`를 `;`로 구분 |
| `label_source` | `manual`, `v1_box`(GT v2 재검토), `model_draft`(학습 라벨 초벌) |
| `revision_action` | `kept`, `adjusted`, `redrawn`, `new` |
| `reviewer`, `review_timestamp_utc` | 작성자, 시각 |

## 10. 일관성 점검

- 작업 완료 며칠 뒤, 무작위로 고른 30개 박스를 기존 박스를 숨긴 채 다시 그린다.
- 두 박스의 IoU 분포(중앙값, 하위 10%)를 보고한다. 이 값은 사람이 낼 수 있는 IoU 상한의 참고값이며 지표 기준을 바꾸지 않는다.

## 11. 미결


- 타일 경계 유지 기준(8절)
- 양산 별도 클래스 분리 여부(3절)
