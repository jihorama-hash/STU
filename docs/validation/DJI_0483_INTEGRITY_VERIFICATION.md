## 2. `_Cut`이 원본의 진부분집합인가

**방법**: 1fps로 그레이스케일 다운샘플(160×90) 프레임을 원본(274개)·`_Cut`(157개) 양쪽에서
추출하고, `_Cut`의 매 초마다 원본 전체와 픽셀 평균절대차(MAD)를 계산해 최적 매칭 초를 찾았다.

**결과**: `_Cut`의 **157개 지점 전부**에서 `offset = matched_orig_sec − cut_sec = 0`,
최적 매칭 거리 **MAD = 0.000**(2위 후보는 0.5~4.9로 뚜렷이 큼 — 우연 일치 아님).

**판정: PASS.** `_Cut` = 원본의 **정확한 프리픽스** `[0, 157.023533s)`. 중간 구간 삭제가
아니라 **꼬리(tail) 컷**이다. 원본 전체 길이(274.374100s) − `_Cut` 길이(157.023533s) =
**117.350567초**가 제거 구간.

(참고: 처음에 64비트 dHash로 시도했으나 정적인 항공 촬영 화면 특성상 해시가 자주 동률이 나서
분별력이 부족했다. 직접 픽셀 MAD 비교로 바꾸자 매칭이 명확해졌다 — 방법 전환 사실을 기록.)

## 4. 호버 위치 대조

`cv2.phaseCorrelate`로 전역 이동량(px)을 측정했다(등록교차의 실제 방법론인 ORB/ECC 유사변환과
같은 계열의 진단).

| 비교 쌍 | shift | response(신뢰도) | 판정 |
|---|---:|---:|---|
| DJI_0482 마지막 프레임 → DJI_0483 첫 프레임 | 0.79px | 0.956 (높음) | 사실상 동일 위치 |
| DJI_0483 마지막 프레임(t=274.15s) → DJI_0484 첫 프레임 | 0.35px | **0.0093 (매우 낮음)** | **비교 자체가 부적절 — §5 참고** |
| DJI_0483 호버종료 프레임(t=157.02s) → DJI_0484 첫 프레임 | 0.50px | 0.0178 (낮음) | 이동량은 작음, 신뢰도는 낮음(아래 해석) |

**해석**: 두 번째 행의 낮은 신뢰도는 애초에 비교 대상이 잘못됐기 때문이다(§5에서 밝히듯 원본의
실제 마지막 프레임은 항공 촬영이 아니다). 세 번째 행(올바른 비교 대상)도 신뢰도가 낮지만,
이동량 자체가 0.50px로 작고 0482→0483(확실히 동일 위치) 사례의 0.79px보다도 작다. 회전교차로는
차량·보행자가 계속 움직이는 동적 장면이라, 4분 30초 간격을 둔 두 프레임은 지나가는 차량·그림자
위치가 달라 위상상관의 뾰족한 피크가 약해진다 — 이는 위치 이탈이 아니라 **장면 동역학** 때문으로
판단한다. 두 프레임을 축소본으로 육안 대조한 결과도 로터리 원형 화단·횡단보도 위치가 화면상 같은
자리에 있어 시각적으로 일치했다.

**판정: PASS (조건부).** 수치·육안 모두 동일 위치를 가리키나, 위상상관 신뢰도가 낮다는 점은
`clips.yaml`에 남겨뒀다. 페이즈 1에서 고정 기준점 기반 정합으로 다시 한번 정밀 확인 권장.

## 5. 제거 구간(157.02s~274.37s)의 정체 — 대표 프레임 6장

균등 간격으로 6장을 뽑아 확인했다(파일: `registration/testcase_0483_removed_frames/`).

| 시각 | 내용 |
|---|---|
| t=157.02s | 아직 로터리 수직 항공뷰(횡단보도·화단 그대로) — `_Cut`이 끝나는 바로 그 지점 |
| t=180.49s | 로터리를 벗어나 수목 지대 상공으로 이동 중 |
| t=203.96s | 나무 캐노피 위, 보행로 근처 상공 |
| t=227.43s | 정자/광장 쪽으로 하강 중 |
| t=250.90s | 지면에 가까워짐 — **드론 자체 그림자가 포장면에 찍혀 있음**(착륙 직전 전형적 장면) |
| t=274.15s(파일 끝) | **렌즈가 손/조끼에 가려짐** — 조종자가 기체를 회수하는 장면 |

**결론**: 제거 구간은 **드론이 호버링 지점을 벗어나 다른 곳으로 비행 후 착륙·회수되는
영상**이다. 회전교차로가 전혀 나오지 않으며, 원본 자체가 애초에 "촬영 종료 → 회항 →
착륙"까지 녹화를 멈추지 않아서 생긴 꼬리다. `_Cut` 편집자가 이 구간을 잘라낸 이유가 명확히
설명된다 — 분석에 쓸 수 없는 영상이라서다.

이 발견은 §4의 "낮은 위상상관 신뢰도" 문제도 함께 설명한다: 원본의 리터럴 마지막 프레임은애초에 비교 대상이 될 수 없는, 완전히 다른 장면이었다.

**총 실관측시간 재산출**: 1,795.059933초로 **수치는 Checkpoint A 당시와 동일**하다. `_Cut`의
길이가 원본의 실사용(호버링) 구간과 정확히 같다는 게 이번에 확인됐기 때문이다. 다만 원본
전체(274.37s)를 그대로 합산하면 안 된다 — 드론 이동/착륙 구간이 섞여 값이 부풀려진다.

**새로 밝혀진 사실**: Checkpoint A에서 "산출 불가"로 남겼던 0482→0483, 0483→0484 공백이
이번에 확정됐다. 특히 0483의 호버링이 실제로 끝나는 시점(157.02s, 절대시각
2026-06-11T12:12:06+09:00)부터 DJI_0484 시작(12:16:34+09:00)까지 **약 268초(4분 28초)의
실제 미관측 구간**이 있다 — 이전에는 "12초 정도인가" 정도로만 짐작했던 부분이 훨씬 컸다.

**테스트 케이스**: `registration/testcase_0483_removed.mp4`(약 118초, keyframe 경계라
목표 구간보다 살짝 김)로 저장. 이 구간은 정적 배경 특징점이 거의 없고(수목 캐노피, 급격한
하강 시점차) 화면 구성이 계속 바뀌어 페이즈 1 정합 알고리즘(ORB+RANSAC/ECC)의 최난도
테스트 케이스로 적합하다.
