## 2. DJI `.SRT`/`.LRF` 확인 (0-2)

8개 비디오 파일 각각의 디렉터리와 저장소 전역을 검색했으나 `.SRT`/`.LRF` 동반 파일을 찾지
못했다. 즉 프레임별 GPS·상대고도·짐벌 데이터를 얻을 방법이 없다.

**영향**:
- 광학식 스케일 계수(`s=(H·p)/f`) 산출 불가 → 페이즈 2는 **실측 기준거리 역산 방식만** 사용
  (구현사양서 §2.2가 이 경우 "역산이 더 정확하다"고 명시하므로 방법론상 불이익은 아님)
- GPS 좌표 기반 호버 표류량 사전 추정 불가 → 페이즈 1의 정합 필요성을 수치로 미리 확인할
  방법이 없고, 정합 전/후 잔차 비교로 사후 확인해야 함
- `clips.yaml`의 `altitude_agl_m`/`focal_length_mm`/`pixel_pitch_um`는 `null`로 남겨둠
  (조종자가 비행 로그를 별도로 갖고 있다면 기입 가능)

## 3. 클립 간 공백 및 실관측시간 (0-3)

`creation_time`(파일 메타) + `duration`으로 클립 종료 시각을 구하고, 다음 클립 시작 시각과
비교했다.

| 구간 | 공백 |
|---|---:|
| DJI_0481 → DJI_0482 | 0.176s |
| DJI_0482 → DJI_0483_Cut | **산출 불가** |
| DJI_0483_Cut → DJI_0484 | **산출 불가** |
| DJI_0484 → DJI_0485 | **12.205s** |
| DJI_0485 → DJI_0486 | 0.176s |
| DJI_0486 → DJI_0487 | 0.009s |
| DJI_0487 → DJI_0488 | 0.043s |

**해석**:
- 대부분 구간(0.01~0.18초)은 사실상 연속 녹화다. 각 파일 크기가 약 3.75GB로 4GB
  부근에 몰려 있는 것을 보면, DJI가 파일 크기 상한(FAT32 4GB 제한 등)에 걸려 자동으로
  파일을 분할했을 가능성이 높다(추정, 비행 로그로 확정 필요).
- **DJI_0484 → DJI_0485 구간만 약 12.2초로 뚜렷하게 크다.** 자동 분할이라기엔 길어서,
  조종자가 의도적으로 촬영을 끊었다 다시 시작했을 가능성이 있다.
- **DJI_0482 → DJI_0483_Cut, DJI_0483_Cut → DJI_0484 두 구간은 산출 불가.** 저장소에
  있는 `DJI_0483_Cut.mp4`는 원본이 아니라 **편집된 버전**이고, 편집 과정에서
  `creation_time` 메타데이터가 사라졌다. 이 두 구간의 실제 공백은 알 수 없다 — 0으로
  가정하지 않고 `clips.yaml`에 `null`로 남겨뒀다.

**총 실관측시간**: 8클립 `duration_s` 합산 = **1,795.06초(29분 55초)**. 이 값은 공백과
무관하게 각 클립의 실측 길이만 더한 것이라, 위의 두 "산출 불가" 구간과 상관없이 신뢰할 수
있다. 프로젝트 CLAUDE.md의 "합계 약 30분"과 일치한다(교차검증 통과).
