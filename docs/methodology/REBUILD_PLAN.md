# 재구축 계획

## 목표

현행 회전교차로 분석 파이프라인의 재현성을 유지하면서 객체·궤적 품질을 먼저 검증하고,
이후 한국 무신호 횡단보도의 횡단사건·보행자-차량 상호작용·안전지표 분석으로 확장한다.
분석과 오프라인 데모는 동일한 버전 산출물을 사용한다. 기존 파일럿과 완료된 배치 산출물은
요구사항, 실패 사례, 기준선 비교의 근거로 보존하되 새 품질 게이트의 확정 결과로
간주하지 않는다.

## 현행 파이프라인 진단

| 단계 | 현재 상태 | 주요 보완 |
|---|---|---|
| 검출·추적 | `tracks.csv`, `summary.json` 생성 | raw detection 별도 보존, 객체사건 GT 매칭 |
| 필터 | `filtered_tracks.csv`, `filter_summary.json` 생성 | 실제 객체 생존율·오제거율 검증 |
| 병합 | `filtered_tracks_merged.csv`, `continuation_report.json` 생성 | fragmentation·ID switch·오병합 검증 |
| ROI 위험후보 | `events.json`, `risk_summary.json` 생성 | 좌표계 명시, 궤적 교차점 기반 PET 검토 |
| 횡단사건 | 미구현 | 접근·대기·진입·차로통과·완료 상태 |
| 상호작용사건 | 미구현 | 보행자-접근차량 pairing 및 완전한 분모 |
| A0/A1/B0/B1/B2 | 미구현 | 선후관계·횡단보도 점유·통과상태 분류 |
| PDI 개념시험 | 미구현 | 약 29.31분 자료의 간이절차, 수동확인 사건만 잠정 DPD |

현행 PET는 같은 ROI의 선행 객체 이탈과 후행 객체 진입 사이의 순차점유 간격이다. 현행
TTC는 후행 객체의 ROI 진입 부근에서 국소 일정속도를 가정한 영상평면 근사다. 둘 다
수동검증이 필요한 잠정 후보이며 확정 상충지표가 아니다.

## 기존 품질 게이트의 취급

이전 계획에는 대표 60초 검출 검증, 추적 정상률 70% 이상, 통행량 수동조사 오차
10~15% 이내, 상충 precision·recall 각각 70% 이상이라는 기준이 있었다. 이 값은 당시
재구축을 진행하기 위한 내부 기준이며 외부 표준이 아니다. 현재 `configs/baseline.json`의
일부 0.7 값도 배치 코드가 자동 집행하는 품질 게이트가 아니다.

기존 값과 검증 이력은 삭제하지 않고 `docs/validation/DECISION_LOG.md` 및 관련 결과
문서에 보존한다. 새 평가에서 사용하는 목표값은 근거와 표본을 명시하고
`internal_provisional_gate`로 기록한 뒤 승인받는다.

## 단계별 품질 게이트

### Gate 0 — 기준선 동결과 단위 점검

- 기준 영상·구간·FPS·모델·임계값·체크섬 기록
- 현행 Homography가 `DJI_0481` 기준 영상 픽셀 정합임을 출력 스키마에 명시
- source pixel, reference pixel, 향후 world coordinate를 분리
- 픽셀 임계값과 실세계 임계값 분리
- 기존 결과를 덮어쓰지 않는 설정·출력 버전 규칙 확정

### Gate 1 — Ground truth와 평가도구

- 객체사건 및 횡단/상호작용 사건 CSV 스키마
- 실제 객체와 자동 트랙 매칭 규칙
- event recall, complete trajectory recall, time coverage
- fragmentation, ID switch, maximum missing gap
- stage-by-stage survival rate

이 Gate에서는 모델·FPS·필터 임계값을 변경하지 않는다.

### Gate 2 — 객체·궤적 품질

- 보행자와 차량을 분리하여 평가
- 원시 tracker trajectory→필터→병합 각 단계의 실제 객체 생존과 오탐 변화 비교
- 내부 목표값은 `internal_provisional_gate`로 기록
- 게이트 미달 시 안전지표 공식 추가보다 누락 원인을 우선 개선

### Gate 3 — 횡단사건과 상호작용쌍

- 보행자 접근·대기·진입·횡단·완료 사건 생성
- 각 횡단사건에 관련 접근차량 연결
- 사람이 확인한 실제 조우 대비 양쪽 유효궤적 확보율 산출
- 후보 생성 전후 결과와 제외사유 보존

핵심 지표는 다음과 같다.

\[
\text{상호작용쌍 관측률}=
\frac{\text{양쪽 유효궤적이 확보된 실제 조우 수}}
{\text{사람이 확인한 실제 보행자-차량 조우 수}}
\]

### Gate 4 — 행동 및 SSM 검증

- 양보·감속·정지·대기시간 규칙 검증
- ROI 순차점유 PET와 향후 궤적 교차점 기반 PET를 별도 필드로 구분
- TTC의 일정속도 가정, 적용시점, 최소거리와 좌표 단위 명시
- 사건별 precision·recall 및 수동검토 상태 보고
- 모든 화면 수치를 원본 트랙과 사건까지 추적 가능하게 유지

### Gate 5 — PDI 개념 반영형 간이분석

- 분석 가능 구간 합계 약 29.31분인 8개 영상에는 정식 지점 PDI와 안전등급을 산출하지
  않음
- A/B 선후관계 및 A0/A1/B0/B1/B2 분류 가능성 검토
- \(S_m,V_m,V_x,a_5\) 또는 명확히 이름 붙인 대리변수 산출
- 수동 확인되고 실세계 변수 품질을 충족한 사건만 `provisional_dpd` 계산
- B2에는 다음 프로젝트 수정식 사용

\[
DPD_{B2}=\frac{1}{1+\exp(0.561a_5+2.713)},\qquad a_5<0\text{ during deceleration}
\]

- `formula_version`과 감속도의 부호·단위 저장
- 표본기간·좌표·속도·분모·한국 적용 한계를 결과에 동시 표시

### Gate 6 — 승인된 설정의 재분석 배치와 데모

기존 7개 영상의 `outputs/analysis/full/` 배치는 완료된 기준선 이력으로 보존한다. Gate 6은
그 이력을 부정하는 단계가 아니라, 앞선 게이트를 통과한 새 설정으로 재분석이 승인될 경우의
절차다.

- 승인된 고정 설정과 새 출력 정체성으로 실행
- 출력 스키마·파라미터·체크섬 검증 후 재개 또는 건너뛰기
- 실제 확인 결과, 미검증 후보, 예시자료를 UI에서 구분
- 분석과 UI를 분리하고 동일한 버전 산출물을 사용
- GPU와 네트워크가 없는 환경에서도 사전계산 결과 재생

## 데모 원칙

- 분석과 UI를 분리한다.
- 모든 화면 수치는 원본 객체·트랙·사건까지 추적할 수 있어야 한다.
- GPU가 없는 장치에서도 사전 계산 결과를 재생할 수 있어야 한다.
- 실제 결과, 미검증 결과, 예시 데이터의 상태를 명시한다.
- 네트워크 연결 없이 실행 가능한 구성을 기본으로 한다.

## 완료조건

각 구현단계는 다음 조건을 모두 충족해야 완료로 본다.

1. 관련 단위·회귀 테스트 통과
2. 동일한 수동검토 표본에서 현재 기준선과 비교
3. 변경 설정과 영향을 받은 파이프라인 단계 보고
4. 출력 스키마 보존 또는 의도적 변경의 버전 기록
5. 재현 가능한 예제 출력과 짧은 검증요약 저장
6. 제한과 제외범위 보고
7. 승인된 방법론 결정을 `docs/validation/DECISION_LOG.md`에 기록

각 Gate가 통과되기 전에는 다음 단계의 전체 영상 GPU 배치를 실행하지 않는다.
