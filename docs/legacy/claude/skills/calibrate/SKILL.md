# 페이즈 2~3 — 스케일 확정과 ROI 디지타이징

근거: 작업지시서 페이즈 2·3, 지표정의서 v0.3 §1.1·§1.5, 구현사양서 §1.3·§2.2

**선행 조건**: 페이즈 1 정합 완료. **정합 전 좌표로 ROI 를 그리면 전부 재작업이 된다.**

## 페이즈 2 — 스케일 계수 V-A

8클립이 동일 위치이므로 **s 를 하나만** 구한다.

### 2-1. 기준거리 측정

기준 프레임에서 실측 가능한 거리를 3개 이상 화소로 측정한다.

| 기준 | 실측값 | 비고 |
|---|---|---|
| 횡단보도 얼룩말무늬 1주기 | **0.90 m** (폭 0.45 + 간격 0.45) | 국내 표준. 가장 신뢰도 높음 |
| 차선 폭 | 현장 확인 | |
| 정지선 길이 | 현장 확인 | |

여러 주기에 걸쳐 재고 나누면 정확도가 올라간다(예: 5주기 = 4.50 m).

### 2-2. s 확정

**역산을 기본으로 한다**: `s = 실측[m] / 화소거리[px]`
`.SRT` 의 `rel_alt` 와 렌즈 제원이 있으면 광학식 `s = (H·p)/f` 와 대조한다.

합격: 기준거리들 간 상대오차 < `geometry.scale_error_tol` (0.03). 초과 시 **4점 호모그래피로 전환**.

→ `clips.yaml` 의 `site.scale_m_per_px`, `site.scale_verified` 갱신

### 2-3. 왜곡 확인

대상 횡단보도 3개소가 화면 중앙 `geometry.center_fraction`(0.60) 안에 있는지 확인한다. 벗어난 지점은 왜곡 보정 없이는 지표를 산출할 수 없다(`NOT_OBSERVABLE` 또는 보정 후 진행).

## 페이즈 3 — 공간 기준요소 디지타이징

**동일 위치이므로 1벌만 만든다.** 기준 프레임(정합 좌표계) 위에 그린다.

### 디지타이징 도구

Claude Code 가 대화형 도구를 만든다. 간단한 HTML/Canvas 페이지 또는 matplotlib `ginput` 이면 충분하다. 요구사항:

- 기준 프레임을 원본 해상도로 표시, 확대/이동 가능
- 요소를 하나씩 순서대로 요청 (아래 표 순서)
- 폴리곤은 클릭으로 정점 추가, 선은 2점
- 완료 시 `calib/rois_v03.json` 저장 + **오버레이 미리보기 이미지 생성**

### 요소별 지침

| 코드 | 형태 | 지침 |
|---|---|---|
| `CW` | 폴리곤 ×3 | **얼룩말무늬 외곽선에 엄격히.** 여유폭 금지. 이것이 오탐 대책의 핵심이 아니다 — 실체에 맞추는 것이 유일한 정답 |
| `CW_ext` | 자동 생성 | CW 를 보행 진행방향 좌우로 각 `regions.cw_ext_margin_m`(1.0 m) 확장 |
| `WZ` | 폴리곤 ×2/횡단보도 | 연석선에서 후방 `regions.wz_depth_m`(2.0 m) 이내 보도 영역. 양측 각각 |
| `SW` | 폴리곤 | 인도 전체 |
| `RW` | 폴리곤 | 차도 전체. E-2x(무단횡단) 판정 기준 |
| `SL` | 선 ×2/횡단보도 | 정지선. 없으면 `has_stop_line: false` + **L1-4 결격 기록** |
| `A5` | 폴리곤 ×2/횡단보도 | 진행방향별 CW 진입 가장자리(SL 있으면 SL) 상류 5 m |
| `D20`,`D30` | 선 ×2/횡단보도 | 접근부 상류 20 m·30 m, 양방향 |
| `TURN` | 폴리곤 | 기존 회전부 ROI 10개를 이관 |

좌표는 **화소 단위로 저장**하고 `scale_m_per_px` 로 실좌표 변환한다. 실좌표를 직접 저장하면 스케일 재검증 시 다시 그려야 한다.

### 검산

디지타이징 후 자동 검산한다.

- CW 폴리곤의 실측 폭·길이가 현장 상식 범위인가 (횡단보도 폭 3~6 m)
- CW ⊂ CW_ext, WZ ∩ RW = ∅, CW ∩ SW = ∅
- A5 구간 길이가 5.0 m ± 0.2 m
- D20·D30 이 CW 로부터 각각 20·30 m

**오버레이 미리보기를 반드시 사용자에게 보여주고 확인받는다.**
