# 절대규칙 자가점검

`CLAUDE.md` 의 절대 규칙 8개가 실제로 지켜졌는지 코드와 산출물을 검사한다. **코드를 쓰거나 고친 뒤, 그리고 페이즈를 마치기 전에 실행한다.**

## 검사 항목

### G-1. 파라미터 하드코딩

`src/` 의 v0.3 모듈(`39_`~`48_`)에서 숫자 리터럴을 찾는다.

```
탐지 대상: 0.10, 0.05, 0.3, 0.5, 2.0, 2.5, 3.4, 1.196, 0.862, 0.561, 2.713,
           30, 100, 0.95, 0.90 ... 및 YAML 에 존재하는 모든 값
허용     : 0, 1, 2 (인덱스·나눗셈), eps, 배열 차원
```

YAML 에 같은 값이 있는데 코드에 리터럴로 박혀 있으면 **위반**. YAML 로드로 교체한다.
YAML 에 없는데 필요한 값이면 코드에 넣지 말고 **YAML 에 근거등급과 함께 추가**한다.

### G-2. 금지된 튜닝

```
- CW 폴리곤을 오탐 감소 목적으로 수정한 흔적 (calib/ 의 git diff)
- 교차각 상한 필터 (예: angle > 140 배제) — 무단횡단자를 지운다
- 임계값을 "결과가 좋아지는 쪽"으로 바꾼 커밋
- 상충 건수를 준수율의 분모로 쓴 코드
```

발견 시 즉시 되돌리고 사유를 보고한다.

### G-3. 단위

```
- V_m 에 km/h 를 넣는 경로가 있는가 → assert 존재 확인
- a5 가 양수로 들어가는 경로 (감속은 음수)
- 가속도가 |a| 인가 a_tangential 인가
- 좌표가 x_px 인가 x_ref 인가 (정합 후 좌표를 써야 한다)
- 클래스가 cls_raw 인가 cls_final 인가 (트랙 단위 확정값을 써야 한다)
```

### G-4. provenance

`runs/` 의 모든 산출 파일에 짝이 되는 `.meta.json` 이 있는가.
`input_files` 의 SHA-256 이 실제 파일과 일치하는가.
`params_hash` 가 현재 YAML 과 일치하는가 (다르면 산출물이 낡았다).

**provenance 없는 파일 목록을 그대로 보고한다.**

### G-5. 게이트와 상태

```
- Stage 1 미통과 상태에서 지표가 산출되어 있지 않은가
- status != 'OK' 인 행의 value 가 null 인가 (0 이면 위반)
- P-PDI 가 값으로 보고되고 있지 않은가 (REQUIRES_LONGER_OBS 여야 한다)
- 컬럼명·표기가 P_PDI_pct / "P-PDI (폴란드 계수 기준 참조값)" 인가
```

### G-6. 통합 금지

준수도·PDI·억제 플래그·L1 을 가중합한 종합점수가 산출되고 있지 않은가.
PDI 와 JDI 를 더한 값이 있지 않은가.

### G-7. 필수 병기

PDI 를 내는 곳마다 `NI`, 유형 구성비, 유형별 평균 DPD, 안전 상호작용 비율이 함께 나오는가.

### G-8. 회전부

`turning=True` 인 상호작용이 PDI·JDI 집계에서 제외되었는가. 로그에는 남아 있는가.

### G-9. 민감도

`run_both_modes`(군집 on/off)와 V-E1~E5 변형이 실제로 산출되었는가.
`sensitivity_variant` 로 구분되어 baseline 과 섞이지 않았는가.

### G-10. 테스트

`tests/` 의 T-1~T-10 이 존재하고 통과하는가. 특히 **T-3(A/B 부호)** 이 실제로 역전을 잡아내는 형태인가 — 통과만 하고 아무것도 검증하지 않는 테스트가 아닌지 내용을 확인한다.
