## 이 프로젝트의 전환점 (반드시 인지할 것)

기존 Phase B 파이프라인은 **PET 상충 검출기**였고 정탐률 19 %로 실패했다.
v0.3 은 이것을 **상호작용 전수 분류**로 바꾼다.

- 열거 단위: "PET 상충" → **"차량–보행개체 상호작용 전부"**
- 주지표: PET/RTTC → **DPD/PDI (연속 위험도 0~1)**
- **"오탐" 개념이 대부분 사라진다.** 인도를 3 m 떨어져 지나간 쌍은 버리는 게 아니라
  DPD ≈ 0.03 으로 정상 계수된다

기존 코드의 처리 방침(폐기/재사용/재작성)은 구현사양서 부록에 있다.

## 절대 규칙

1. **파라미터를 코드에 하드코딩하지 않는다.** 전부 `docs/무신호횡단보도_파라미터_v02.yaml`(현재 v0.2.1)
   에서 읽는다. `docs/무신호횡단보도_파라미터_v01.yaml`은 superseded이며 더 이상 참조 대상이 아니다
   (삭제하지 않고 보관).
   필요한 값이 YAML 에 없으면 코드에 넣지 말고 YAML 에 근거등급과 함께 추가한다.
2. **오탐을 줄이려고 ROI 를 좁히거나 각도 필터를 넣지 않는다.**
   `CW` 는 노면표시 실체에 맞추는 것이 유일한 정답이다.
   각도 상한 필터는 **차도를 따라 걸어오는 무단횡단자(진짜 위험)를 지운다.**
   구분은 각도가 아니라 횡방향 이격거리 `S_m` 이 한다.
3. **결과가 좋아지는 방향으로 임계값을 조정하지 않는다.** 변경 시 민감도 분석을 함께 낸다.
4. **Stage 1 검증 게이트를 통과하기 전에는 지표를 산출하지 않는다.**
   강행 시 모든 값 `null` + `status='GATE_FAILED'`.
5. **표본 미달 지표는 0 이나 빈칸이 아니라 사유 코드로 출력한다.**
   `INSUFFICIENT_SAMPLE` / `GATE_FAILED` / `NOT_OBSERVABLE` / `REQUIRES_FIELD_SURVEY` /
   `REQUIRES_LONGER_OBS` / `PENDING_VERIFICATION`
6. **준수도·PDI·억제 플래그를 가중합해 종합점수를 만들지 않는다.** 가중치 근거가 없다.
7. **모든 산출 파일에 `.meta.json` (provenance) 을 붙인다.** 없는 수치는 리포트에 쓸 수 없다.
8. **체크포인트에서 멈추고 보고한다.** 끝까지 밀어붙이지 않는다.
9. **파라미터 파일을 in-place 수정하지 않는다.** 값·주석·근거를 바꾸면 `meta.version` 을 올리고
   `changelog` 에 사유를 적는다. 파일 상단 배너 버전도 함께 맞춘다.

## 용어

| 기호 | 뜻 |
|---|---|
| `I` | 상호작용. 차량 1대 × 보행개체 1개의 스침 사건. **열거 단위이자 PDI 의 분모** |
| `NI` | 상호작용 총수 (A0+A1+B0+B1+B2). 안전 상호작용을 **포함**한다 |
| `E-1` | 조우. 정지판단선 통과 시점에 보행자가 WZ∪CW 에 있던 경우. **준수도의 분모** |
| `E-2x` | 무단횡단 기인 상호작용. 준수율에 넣지 않고 JDI 로 별도 집계 |
| `t_m` | 통과시점. 차량 전면이 보행개체 근접 가장자리와 일치하는 순간 (선형보간) |
| `S_m` | t_m 의 횡방향 이격거리 [m]. `≤ 0` 이면 충돌 |
| `V_m` | t_m 의 차량속도 [**m/s**] — km/h 아님 |
| `a₅` | CW 상류 5 m 구간 최대 감속도 [m/s²]. **음수** |
| `DPD` | 상호작용별 연속 위험도 0~1 |
| `PDI` | ΣDPD / NI × 100 [%]. 반드시 **"P-PDI (폴란드 계수 기준 참조값)"** 로 표기 |
| `JDI` | 무단횡단(E-2x) 위험 지수 |

**유형**: `A0` 차량이 앞을 지남·보행자 아직 보도(안전) / `A1` 차량이 앞을 지남·보행자 차도 위 /
`B0` 보행자 진입 전 차량 정지(안전) / `B1` 보행자 횡단 중 차량 진입 / `B2` 횡단 완료 후 차량 진입

> **기호 재사용 주의**: `V-E6` 은 현재 `cei.variants` 의 CEI 4조합 산출을 가리킨다. T-2 검증 이전
> 문서에서 같은 기호가 다른 의미로 쓰인 사례가 있으므로, 옛 문서를 참조할 때 기호만 보고
> 판단하지 않는다.

## 코딩 규약

- **단위 assert 필수.** `V_m` 에 km/h 를 넣으면 조용히 틀린다.
- **가속도는 진행방향 성분**(`a_tangential`)을 쓴다. `|a|` 를 쓰면 곡선 주행의 구심가속도가 섞인다.
- **t_m 은 선형보간.** 가장 가까운 프레임으로 반올림하지 않는다 (30 fps·30 km/h 에서 1프레임 = 0.28 m).
- **클래스는 트랙 단위 확정값**(신뢰도 가중 다수결)을 쓴다. 프레임 단위 `cls_raw` 를 직접 쓰지 않는다.
- **좌표는 정합된 기준 프레임 좌표계**(`x_ref`,`y_ref`)를 쓴다. 원본 화소 좌표를 직접 쓰지 않는다.
- **단위테스트를 먼저 쓴다.** 특히 `T-3`(A/B 판정 부호) — 뒤집히면 전체 결과가 무의미해지는데
  에러 없이 조용히 틀린다.

## DPD 확정식

```python
# 계수는 YAML dpd_coefficients 에서 로드할 것. 아래는 참조용.
DPD_A1 = 1/(1+exp( 1.196*S_m - 0.075*V_m - 0.923))   # 원문 식(2)
DPD_B1 = 1/(1+exp( 0.862*S_m - 0.052*V_m))           # 원문 식(3)
DPD_B2 = 1/(1+exp( 0.561*a5  + 2.713))               # 식(4) 수정판
DPD_A0 = DPD_B0 = 0
```

> **원문 식(4)는 계수 2개가 전치된 오타다.** 원문 표기 `exp(2.713*a5 + 0.561)` 은 치역 하한이
> 0.363 인데 논문 자신이 보고한 값(0.051·0.064·0.200·0.262)이 전부 그 아래다.
> 근거 4건은 `claude/03_PDI_DPD_검증_및_한국형PoC_v01.md` §2.3.
> **코드 주석에 이 사실을 반드시 남긴다.**

## 알려진 한계 (리포트에 고정 수록)

- DPD 는 설문 기반 **인지위험**이지 상해위험이 아니다. DPD 0.5 는 사망확률 50 % 가 아니다.
