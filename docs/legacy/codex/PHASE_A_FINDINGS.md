## A-1. 프레임 정합 오차 실측

### 방법

8개 영상(DJI_0481~0488)의 첫/중간/끝 프레임을 추출, DJI_0481 첫 프레임을 기준으로
ORB(6000 특징점) + RANSAC homography를 추정해 5개 ROI 대표점이 기준틀에서
몇 px 이동해 보이는지 측정했다.

- 스크립트: `src/21_measure_frame_alignment.py`
- 산출물: `runs/phaseA_alignment/alignment_offsets.csv`, 중첩 비교 이미지(`overlay_*.jpg`)

### 결과 (ROI 대표점 최대 이동량, px)

| 영상 | 첫 프레임 | 중간 | 끝 | 비고 |
| --- | ---: | ---: | ---: | --- |
| DJI_0481 (기준) | 0 | 50 | 46 | 기준 영상조차 비행 중 ~50px 드리프트 |
| DJI_0482 | 47 | 69 | 69 | |
| DJI_0483_Cut | 65 | 71 | 98 | |
| DJI_0484 | 104 | 118 | 85 | |
| DJI_0485 | 84 | 83 | 45 | |
| DJI_0486 | 40 | 92 | 117 | |
| DJI_0487 | 116 | 100 | 188 | |
| DJI_0488 | 179 | 160 | (측정불가) | 끝부분 특징점 매칭 실패(inlier 5개) — 기체 이동/복귀 구간으로 추정 |

### 판정

1. **영상 간 어긋남은 40~180px, 영상 내 드리프트도 45~190px.** 호버링 중에도 바람에 의한
   이동이 상시 존재하므로, "같은 위치에서 찍었으니 픽셀 좌표가 같다"는 가정은 성립하지 않는다.
2. **통합 히트맵의 점 위치는 최대 ~190px(차량 1대 폭 이상) 번져 있다.** ROI 단위 집계는
   ROI 폴리곤이 충분히 커서 대체로 유효하지만, ROI 경계 부근 이벤트는 오분류 가능성이 있다.
3. **DJI_0488 끝부분처럼 기체가 이동한 구간이 데이터에 섞여 있다** → 편집 단계에서
   안정 호버 구간 선별이 필요하다는 직접 증거.
4. 이전 검토에서 ROI json 좌표 차이(최대 ~780px)로 추정했던 정합 문제는 과대평가였다.
   실제 원인은 (a) 프레임 어긋남 40~180px + (b) 0482 ROI를 손으로 다시 그리며 생긴
   작도 편차(중심점 기준 최대 ±320px, 방향 불규칙)의 합성이다. 단, 최종 통합 분석은
   0482도 공통 ROI(step3roi 변형)를 사용했으므로 ROI 불일치 문제는 이미 회피되어 있다.

### 방법론 반영 사항

- 본분석에서는 **모든 프레임을 기준 프레임(또는 정사영 지도)에 정합(registration)하는
  전처리 단계를 필수**로 넣는다. ORB+RANSAC 기반 프레임 정합은 이미 검증된 방식이며
  계산 비용도 낮다.
- 개선 전·후 비교를 위해서는 픽셀 기준틀이 아니라 **지상 기준점(GCP) 기반 homography로
  실세계 좌표계**를 써야 한다(공사 후에는 도로 기하가 바뀌므로 개선 전 프레임 기준틀
  자체가 무효화됨). GCP는 공사에도 보존될 지물(건물 모서리, 맨홀, 옹벽 등) 4점 이상.

## A-2. 시간 샘플링(유효 fps) 민감도

### 방법

같은 영상(DJI_0482), 같은 ROI(0481 공통 ROI), 같은 PET 로직으로
step3(유효 10fps)과 step10(유효 3fps) 결과를 비교했다.

- 스크립트: `src/22_quantify_step3_vs_step10.py`
- 산출물: `runs/phaseA_step3_vs_step10/step3_vs_step10_summary.json`, `roi_entries_comparison.csv`
- 이벤트 단위 매칭은 기존 `step3_to_step10_pet_event_classification.csv`(52건 분류) 활용

### 결과

| 항목 | 10fps (step3) | 3fps (step10) | 3fps의 손실 |
| --- | ---: | ---: | ---: |
| PET 이벤트 전체 | 52 | 30 | -42% |
| **보행자-차량 상충** | **23** | **8** | **-65%** |
| 차량-차량 상충 | 29 | 22 | -24% |
| final(PET≤1.5s) 이벤트 | 36 | 22 | -39% |
| 궤적 중위 지속시간 | 0.4s | 0.0s | 절반 이상이 1점짜리 유령 궤적 |
| 궤적당 평균 관측점 | 14.2 | 4.2 | |
| ROI 진입수(노출 분모) | — | — | ROI별 ±10~30% 변동 |

이벤트 매칭 분석(step3 52건 기준): 3fps에서 재현된 것은 21건(40%)뿐.
손실 원인의 대부분(20건)은 **상충 당사자의 ROI 통과 자체가 3fps 샘플에 잡히지 않음** —
즉 알고리즘 문제가 아니라 순수 샘플링 부족.

### 판정

1. **3fps(step10)는 예비 분석용으로만 유효하다.** 특히 캠퍼스에서 가장 중요한
   보행자-차량 상충이 65% 누락되므로, step10 기반의 현재 통합 결과는
   "위험 지점의 상대 비교"로만 쓰고 절대 건수로 인용하면 안 된다.
2. 보행자-차량 상충이 차량-차량보다 샘플링에 훨씬 민감하다. ROI 통과 시간이 짧은
   보행자 특성 때문으로, **본분석 최소 요구 유효 fps는 10fps, 권장은 원본 30fps 전량 처리.**
3. 1,119개의 person 궤적(5분 영상)은 실제 보행자 수의 수십 배 — 현행 그리디 IoU 추적기의
   분절이 심각하다는 뜻. 노출 분모(진입수)가 이 분절에 오염되므로
   **Kalman 기반 추적기(ByteTrack/OC-SORT) 교체는 필수**이며, 그 효과는 A-3 수동조사로 정량화한다.

## A-3. 지상검증 수동조사표

### 산출물

`survey/지상검증_수동조사표_v1.xlsx` — 6개 시트:

| 시트 | 내용 | 사전 기입 |
| --- | --- | --- |
| 0_안내 | 목적, 조사 순서, 용어·판정 기준 | — |
| 1_촬영로그 | 영상별 촬영조건 기록(고도·날씨·풍속·그림자 등) | 영상 ID, 해상도 |
| 2_통행량조사 | DJI_0482 대상, ROI 5곳 × 1분 구간별 유형별 진입 수동 카운트 + 자동값 대조표(오차율 자동계산) | ROI·구간 틀, 대조 수식 |
| 3_궤적검증 | 보행자 궤적 표본 30개 추적 품질 판정(정상/분절/ID스위치/부분누락/오검출) | track_id, 출현시각, 시작·종료 좌표 |
| 4_상충검증 | 자동 검출 상충 이벤트 183건 전수 판정(실제상충/단순통과/오탐/판단불가) + 정탐률 자동 집계 | 8개 영상 이벤트 전체, critical 행 강조 |
| 5_자동집계참고 | 자동 진입수(10fps/3fps) — 수동 집계 완료 전 열람 금지 | 전체 |

### 조사 우선순위 (시간이 제한될 경우)

1. **4_상충검증의 critical 52건** — 정탐률이 낮으면 위험도 산정 체계 자체를 재설계해야 하므로 최우선
2. **2_통행량조사** — 노출 분모의 신뢰도 확정 (약 30분 소요)
3. **3_궤적검증** — 추적기 교체 효과의 기준선(baseline) 확보
4. 여유 시 수목·그림자 많은 영상 1편(예: DJI_0486) 추가

## 종합: Phase B에 반영할 확정 사항

1. **좌표계**: 프레임 정합 전처리 필수 + 개선 전·후 비교용 GCP 기반 실세계 좌표계 도입
2. **샘플링**: 최소 유효 10fps, 권장 30fps 전량 처리 (하드웨어 사양은 이 기준으로 검증)
3. **추적기**: Kalman 기반으로 교체 (분절 1,119 → 실보행자 수준으로 감소가 목표,
   A-3 조사로 개선 폭 측정)
4. **편집 SOP**: 안정 호버 구간 선별(0488 끝부분 유형 제거), 분석 단위 표준화, 촬영 로그 필수화
5. **지표 체계**: 보행자-차량 / 차량-차량 상충 분리 보고 유지, critical 판정 규칙은
   A-3 정탐률 확인 후 확정
6. **현행 Pilot 결과의 지위**: ROI 간 상대 비교용 참고자료. 절대 건수·비율은
   본분석에서 재산정
